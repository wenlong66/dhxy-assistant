# 日常任务实测记录

测试日期：2026-11-11，时间均为北京时间（UTC+8）。

## 执行规则

- 有金扫帚时自动使用，优先竞技场，其次宝图任务。
- 完成任务后可能新增金扫帚；每项任务结束并返回列表时重新检查数量，不能沿用先前的 0。竞技场已完成则跳过，新增扫帚优先用于尚未完成的宝图。
- 然后按「今日必做」第一排开始的列表顺序处理剩余任务；不固定为师门、帮派、宝图、五环的顺序。
- 领取帮派前的截图顺序：帮派、五环、师门、宝图。
- 完成后列表会重新排序；每次检查当前列表，从第一排重新选取下一项未完成任务，不复用旧位置。帮派完成后的顺序为五环、师门、宝图。
- 普通任务只操作领取，之后由游戏自动执行；等待预估时间后核对完成状态，确认完成再领取下一项。
- 已完成的任务跳过。等待时间到、单环完成提示或仍显示「前往」，都不能单独作为整项完成依据。

## 首版接入

- `daily_tasks.py` 复用 Maa 本地 OCR/截图/点击；`gui_backend.py` 和 GUI 后台线程提供只读「检查日常列表」及「开始日常任务」。日常与答题分别启动，不调用 AI。

- 领取后必须看到对应右侧进度；取消/停止会阻止下一次点击。等待超时、未识别页面或计数异常时暂停并保存本地诊断。

- 测试夹具仅保留用户截图中实际 Maa OCR 的任务相关文字、分数和位置；不包含原始截图、聊天或账号资料。

## 2026-11-12 现场故障修正

- 活动点一次未打开时原先仅等待，现改为重新观察后重试，活动、扫帚各最多 3 次；已打开则跳过，完成任务后返回列表也适用。
- 现场 OCR 将帮派的「日次数：20/20」读为「次数：20/20」，原先要求「日次数」前缀导致误停。现在只在次数所在行解析数字，次数读不清时保留为未知，不阻塞已识别的领取按钮。
- 按用户补充规则，完整任务卡片没有「前往／立即完成／一键完成」即判为完成；仍保留已读到满次数时跳过的判断，兼容竞技场 3/3 仍显示前往的情况。

- 现场竞技场奖励提示还遮住了其他任务标题；增加最多 15 秒的稳定识别等待，暂时遮挡消失后继续，不立即暂停。
