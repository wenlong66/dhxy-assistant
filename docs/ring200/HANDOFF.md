## 2. 修复经过与废弃方案

### 2.1 人物／云宫拼图外框误判

**原始症状：** `拼图外边缘不明确，未尝试交换。`

- 图13人物衣服的浅色内容落在内部边缘，被误认为外框；最初将内部浅色覆盖率上限从0.3放到0.5，只解决人物图。
- 图14云宫内部云雾浅色覆盖率接近98%，说明单纯放宽浅色阈值无法区分画面内容和外框。
- 最终改为利用暖米色色差识别外框，并恢复原覆盖阈值；当前校准与接入约束见 [公共拼图接入](README.md#公共拼图接入)。
- 用户强调「每次拼图不是固定的」；没有采用固定图片答案、固定点击序列或盲点试错方案。

### 2.2 歌王／问题鬼答错后未重试

- 初期只支持「诗词鬼」，歌王失败画面没有进入原关闭重试入口；之后扩充了同一入口，没有另建唱歌答题流程。
- 最近保存现场为第34环、底部NPC「问题鬼」，最终诊断为：`200环环数超过3分钟未变化，疑似任务停住，请检查答题、战斗对话、技能书购买或组队状态；未自动购买或退队。`
- 根因是NPC名单缺少问题鬼，不是AI配置问题，也不是应该关闭全局提交防重。
- 最初补充问题鬼时仍要求完整失败台词；用户随后明确说「其实判断名字就行了，对话框里的内容不重要」「也就是台词不重要」。此前名字加完整台词的方案已废弃，当前规范见 [失败对话识别](README.md#失败对话识别)。
- 名单遗漏和台词限制分别由回归测试跑红后修复；不要把旧对话或记忆中的完整台词限制重新加回来。

### 2.3 题干装饰被识别为低置信度字符

**原始症状：** `OCR 区域 question 未通过：Missing/low-confidence OCR text; inspect the ROI, do not guess.`

- 图17装饰图标被OCR为 `3`，置信度约0.103618；真实题干约0.986717。原 `join_blocks()` 因任意低置信度块拒绝整段。
- 最终提取共享的装饰过滤逻辑，初次识题与反馈关联一致；当前范围见 [题干装饰图标](README.md#题干装饰图标)。
- **曾尝试并撤销：** 将题干ROI收缩成旧文字的紧包围框。这样会漏掉换题后在旧框外新增的「不」等字，可能将新题反馈关联到旧题。
- 最终保留完整题干区域，并增加「框外、完整题干区内新增字必须拒绝反馈关联」回归。临时 `inspect_frame()` 已移除；不要按早期草案继续调用。
- 也未采用全局把题干左界移到210／214的方案，因为旧题正文可能从更左侧开始。

### 2.4 高分辨率拼图交换确认误判（2026-11-26）

- 16:16:50现场保存为1600×900云宫拼图，报「拼图交换未确认」，OCR为已操作1次、剩余9次；仅有交换后截图，不能还原本次完整点击过程。
- 离线复现了相同报错：正确交换后，旧图块采样先取整裁切、再最近邻缩放，产生位置相关的亚像素偏移，导致内部像素平均差超过原阈值3；不需要动画或OCR错误即可触发。
- 修复仅将公共 `puzzle_tiles()` 改为全帧像素中心坐标的双线性采样；未放宽匹配阈值、外框识别、次数校验、随机输入、停止保护或增加重试，未新增依赖。
- 新增回归覆盖三套图片、各24种排列、830×466与1600×900的正确交换和未交换拒绝，以及按模拟点击推进画面的完整执行；后者修复前在六组场景均复现原报错。
- 本次拼图23项、全量500项离线测试通过，`git diff --check`通过。未连接设备发送输入；本次实机故障是否完全由该缺陷造成、修复后是否正常续环，仍需重启助手验收。

### 2.5 拼图成功过渡帧误暂停（2026-11-26）

- 16:58:53现场截图已显示「挑战成功」及复原画面，但成功提示遮挡倒计时，OCR保留关卡、标题及已操作1次／剩余9次，未读到秒数；`verify_swap()` 立即调用严格 `puzzle_state()`，在自动关窗前抛错。
- 最小回放在修复前复现同一报错。修复仅让两次交换点击后的观察阶段在原3秒时限内等待可读状态或页面退出，不补点、不依靠缺失文字猜成功；持续不明仍报错，点击前校验保持不变。
- 新增成功过渡后自动关窗、持续不可读超时、点击前拒绝、等待中停止，以及关窗后回到200环监控且不重点击任务的回归。全量505项通过，`git diff --check`通过。
- 用户现场已确认拼图交换成功；本修复尚未实机验证，不把静态截图或合成回放等同于修复后自动续环验收。

记录时工作树存在日常、GUI、答题、拼图、200环、文档及fixtures的大量已有修改，不能全部归因于最后的NPC修复。

- 用户没有要求提交或推送，本会话没有创建commit或push；不要覆盖或回滚其他工作。

建议按以下顺序接手：

1. 运行 `git status --short`，先读正式文档与公共规则，确认其他会话没有新增改动。
2. 重启助手加载代码，由用户启动200环，依正式文档验收失败重试、安全中断、正常推进和完成行为。
3. 验收拼图实机交换与自动续环；获取脱敏真实反馈图后再校准正确对勾。
4. 若再次暂停，查看当次新保存的截图、OCR与性能诊断，为新现象建立最小回归；不要重做已完成修复或放宽全局保护。
5. 后续代码变更按正式文档运行相关与全量测试；验收完成后更新本记录的状态，业务变化只更新正式文档及必要的公共规则。
