# 200环任务

本文件是200环功能的正式说明与维护规范，统一维护该活动的入口、领取、推进、交互、保护及验收要求；[会话交接记录](HANDOFF.md) 只保存修复历史、当时的验证结果和待办，不另行定义业务规则。

## 使用与职责

在助手界面点击「开始200环」。助手负责进入任务、按名额领取新一轮，以及处理已校准的答题、失败对话、开战对话和拼图；寻路、战斗及正常下一环由游戏执行。

- 完成一轮后结束，不自动开启下一轮。
- 不自动购买技能书、交物品、退队，或处理未知NPC、未知「使用」弹窗、登录及安全验证。
- 操作前的随机落点、0.3–1秒可停止等待、新截图复核及停止保护，遵循 [公共自动输入规则](../../AGENTS.md#模拟器自动输入)。旧截图未过期不等于可以点击。
- 答题策略、题库学习和公共拼图是共享能力，不因200环、唱歌题或不同NPC另建实现。

## 入口与领取

### 从当前页面启动

1. 已有答题弹窗或已校准失败对话时，先处理答题，不先进入活动列表。
2. 从主界面启动时，先确认右侧选中「日常」。若为「活动」，随机等待后重新截图核对页签，再点击「日常」；确认切换后检查第一项。
3. 仅日常第一项是200环时允许直接续环；不点击其他任务，也不点击下面的200环项。
4. 点击首项前重新截图，复核仍为首项、标题及环数一致，按新画面目标范围随机取点。
5. 第一项不是200环时，从活动 → 周月常查找200环卡片，未显示时在卡片列表内向上滑动，最多6次。

### 从活动卡片领取或续跑

只使用**同一张200环卡片**的「已领取：已领/上限」判断名额，不能借用其他卡片的次数。

| 卡片状态 | 允许行为 |
| --- | --- |
| 已领小于上限，例如0/1 | 点击「前往」，由护园大将领取新一轮 |
| 名额用完，卡片明确有进行中的任务 | 只允许续跑已有任务 |
| 名额用完且没有明确进行中的任务 | 不领取、不自动开新轮 |
| 次数缺失、无效或读不清 | 不点击 |

- 「前往」前随机等待、重新截图，复核卡片、次数及目标位置。
- 到达NPC后，只允许点击「护园大将」的完整选项「有什么可以帮助你的（领取200环）」；点击前再次等待、新截图并复核NPC及完整选项。
- 领取后等待新的200环追踪或已校准任务画面，不因追踪尚未出现而重复领取。

## 自动推进、环数与完成

### 正常推进

助手只在启动时尝试任务入口；后续不逐环重复点击日常任务。处理答题、已校准开战对话或拼图后，交回游戏自动推进。

唯一的额外入口恢复见下文「答题与失败重试」：失败对话关闭后若回到主界面，可在同环首项确认后尝试一次续环，不推广为正常逐环点击。

### 环数读取与遮挡

- 总数固定200，只读取日常首项标题中 `（当前环数/` 的完整当前数字，不要求 `/` 后的总数或右括号可见。
- 缺少 `/` 时不猜截断数字；有效当前环数为1–200，保留进度倒退保护。
- 已确认200环标题、但当前数字未读清时，按原轮询周期等待新截图，不点击，也不因此暂停。
- 遮挡不计入停滞时间；恢复识别后重新计时。

### 完成条件

满足任一条件即结束本轮，不再点击或自动领取下一轮：

1. 可靠识别到当前环数200。
2. 最后确认第199环后，正常主界面右侧选中「日常」，连续两帧都没有200环追踪。

切换页签、弹窗遮挡、仍可见的残缺标题及较早环数缺项，不属于第二种完成证据；拼图弹窗消失也不代表整轮完成。

### 停滞与点击前页面变化

- 环数长时间不变才按疑似停滞保存现场提醒，当前阈值为3分钟；正常监控约每5秒检查，不改动既有轮询和超时。
- 可能原因包括技能书购买或被队友拉入队伍，不自动购买或退队；未校准阻塞需要用户补图。
- 停顿后复核发现环数前进、开始寻路、进入答题／拼图／已校准开战对话或短暂遮挡，只取消旧目标点击并重新检查，不直接停止整轮。
- 停止请求、分辨率变化、进度倒退、持续超时、识别异常及无法确认的输入，仍保留相应保护。

## 答题与失败重试

### 公共答题入口

200环调用统一答题流程，支持2–4个真实文字选项；仅按已校准布局、真实题干、选项和按钮识别，不要求任务标题、环数或弹窗标题。唱歌题与普通题完全共用策略、账号题库和提交逻辑。

正常答题概率、AI配置、唯一正确对勾学习、矛盾答案隔离及防重要求，以 [统一答题与题库学习规则](../../AGENTS.md#统一答题与题库学习) 为准；200环不另设一套概率、AI配置或题库。

题干有完整高置信度文字行、却夹杂低分检测框时，在同一截图上按覆盖全部框的整行区域复读一次，不直接丢掉可能的数字或否定词；复读改变已确认的数字／否定词时拒绝该结果。仍未读清的部分显示为`*`，同题比较按通配符忽略；同组选项映射与按钮稳定时，未知题干或可读状态／像素抖动按公共规则随机兜底，不反复截图卡住，也不以星号或不可靠题干学习答案。

预览、复核与提交共用规范身份，恢复清晰题干不开放第二次提交。持久提交身份另用题干笔画指纹排除背景与孤立噪点，避免重建读取器后重复点击；识题、明确换题和反馈仍检查完整题干范围。选项、布局、明确换题或截图新鲜度校验失败时，本次不点击，随机等待1–2秒后重新截图，持续失败保留原3分钟停滞超时。

### 失败对话识别

**只识别底部已校准的「诗词鬼」「歌王」或「问题鬼」完整名字，不读取或判断台词。** 台词变化、缺失或未被OCR识别，不阻止这一入口；名字读不清、低置信度或为其他NPC时不授权点击。

1. 确认NPC名字后随机等待，期间保持可停止。
2. 等待后检查停止标志、重新截图，确认分辨率未变化且仍是同一个NPC。切换到另一个已知NPC也不能沿用旧目标。
3. 在新截图确认的下方对话区域内随机点击一次，然后等待对话关闭。
4. 对话持续时不连点、不开放新的答题实例；只有确认关闭后才重新识题。
5. 若直接出题，使用统一入口作答；若回主界面，仅在日常首项仍为同一环时尝试一次续环，以再次出题。

### 重试实例与防重复提交

- 确认对话关闭后，`on_quiz_retry` 调用 `UnifiedQuizReader.confirm_retry()`，建立新的弹窗提交实例。
- 后端重新读取题目，只把同题旧 `pending` 提交记为 `unknown`，解除待反馈阻塞；不影响其他题的待反馈记录。
- 不凭NPC或失败提示猜正确答案，不用排除法写库；不放宽 `QuizStore.claim_submission()` 的全局防重。
- 新实例的预览、复核与提交仍沿用同一次策略选择，同一重试画面不允许重复提交。

### 题干装饰图标

- 仅忽略已校准题干小装饰区内、具有实际彩色装饰像素证据且完整落在区域内的OCR块；排除后必须保留真实文字。
- 不全局删除低置信度块、不降低真实文字阈值，保留数字、否定词及跨越装饰区的文字保护。
- 初次识题、提交前复核和反馈题干关联使用同一过滤逻辑；始终检查完整题干ROI，不能缩成旧文字的紧包围框，以免漏掉换题新增文字。
- 当前只覆盖已校准位置及颜色证据，其他装饰样式需要另行校准。

## 已校准开战对话

| 怪物 | 必须确认的完整开战选项 |
| --- | --- |
| 夺魄妖王 | 看你往哪里跑。 |
| 斗志幻影 | 切磋一番 |

两种怪物共用开战流程：随机等待后重新截图，复核同一怪名与完整选项，只点一次，不点「再见」；之后等待游戏自动战斗和续环，不操作战斗。其他怪物不能套用模糊匹配，需要先提供对话画面校准。

## 公共拼图接入

复用 [公共拼图规则](../../AGENTS.md#公共拼图) 与 [puzzle_tasks.py](../../puzzle_tasks.py)，不为200环复制求解逻辑。

- 拼图图片与排列每次不同，不保存某张图的固定答案或点击顺序，也不盲点试错。
- 当前布局按随图块移动的暖米色外框唯一判断角位；现有颜色校准在原条件上要求 `red - green > 10`、`green - blue > 15`，外／内边缘覆盖阈值分别为0.7／0.3。BGR通道先转整型再计算。
- 交换成功或拼图页面退出后交回200环流程，由游戏自动续环，不额外重复点击任务；不能将弹窗消失当作整轮完成。
- 两次交换点击后的复核阶段，成功提示可能遮住倒计时：在原有3秒交换确认时限内只等待新截图，页面退出后交回活动流程，不因单帧关卡／次数／倒计时缺失立即暂停，也不补点。持续无法确认仍暂停；点击前的完整校验不放宽。

## 诊断与静态校准

- 最近运行现场保存于本地 [screen.png](../../data/maa/ring200/screen.png)、[ocr.json](../../data/maa/ring200/ocr.json)、[performance.json](../../data/maa/ring200/performance.json)；会被下一次运行覆盖，不是永久fixture。
- 原始运行截图已是游戏画面，不重复去外框。历史879×510带模拟器外框附件用 `crop((4, 40, 834, 506))` 得到830×466；不能把这一裁切套用到所有截图。
- 图像数组为BGR。静态校准使用 `CustomController`、`execute=False`，不连接真实模拟器发送输入；`runtime_dir` 使用 `Path`。
- Windows使用项目虚拟环境并显式启用UTF-8；读取外部图片的Python使用 `-I`，脚本与不可信下载内容分开放置。
- 完整截图、账号聊天、SQLite题库和AI密钥不提交、不上传；回归仅使用脱敏裁图和OCR。AI本地配置已忽略，不能为OCR或重试排错读取、打印密钥，也不通过删除未知持有者的设备锁排错。

### 验收标准与边界

- 离线验证随机落点不越界、等待在0.3–1秒内且有变化；等待中停止、截图过期、页面／NPC变化、切题时不会发送旧目标输入。
- 验证失败对话只关闭一次，关闭确认后才允许新实例，同题重试仍防重复提交；不根据失败提示写入答案。
- 验证正常推进不逐环点任务、遮挡不误停、最终完成不自动开下一轮，以及拼图交换后交回游戏。
- 静态真实截图OCR、合成图、mock与离线回放通过都不等于实机验收；正确对勾检测还需要真实答对／答错反馈截图校准，不能仅凭mock关联测试宣称自动学习已实测。
- 已执行结果和未完成实机验收的具体项目，统一记录在 [交接记录](HANDOFF.md#3-最近验证与待验收项)，不把历史测试次数当作永久能力承诺。
