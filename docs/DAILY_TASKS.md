# 日常任务规则与维护说明

本文面向维护日常自动化的开发者与编码助手，整理本次会话已确认的业务规则、配置位置、故障边界和验收要求。修改日常流程前先读本文；操作步骤见 [GUI 使用说明](GUI.md#日常任务)。

本文是日常专属规则的规范入口；公共输入安全与题库学习规则仍由 [AGENTS.md](../AGENTS.md) 定义。[日常实测记录](DAILY_TASK_TEST.md) 保留历史截图、手动采集和当时实现，不覆盖本文的当前规则。200 环是独立流程，见 [200 环文档](ring200/README.md)。

## 1. 支持范围与入口

| 日常 | 日次数上限 | 已接入的处理方式 |
| --- | --- | --- |
| 帮派任务 | 20 | 普通领取后等待游戏自动执行 |
| 五环任务 | 1 | 活跃度条件下普通领取，随后等待游戏自动执行 |
| 师门任务 | 20 | 普通领取后等待游戏自动执行 |
| 宝图任务 | 15 | 金扫帚、文牒通关或普通领取 |
| 卓越竞技场 | 3 | **仅金扫帚，不执行普通竞技场** |
| 大理寺答题 | 10 | 有扫帚直接完成，无扫帚自动答题 |

- 只处理本次勾选的任务。野外封妖不在自动处理范围内。
- 「开始日常任务」可从游戏主界面启动：左上角「活动」→右下角金扫帚→任务列表。活动面板或扫帚列表已打开时，跳过已完成的入口步骤；不为进入扫帚额外切换活动页签。
- 「检查日常列表」仅对已经手动打开的列表截图、识别，不自动导航、点击或调用 AI，也不是开始日常的前置步骤。
- 活动和扫帚入口各最多尝试 3 次；已打开时不重复点。遇到「用了金扫帚，日常不用愁」引导时，关闭一次并确认消失，再继续；5 秒仍未关闭则暂停，不连点。
- 当前几何校准基于 834×470 的 16:9 游戏画面，并有倍数坐标回放。其他门派 NPC、日常列表滚动及 UI 改版需要补图校准，不套用未确认的坐标。

## 2. 调度顺序

### 剩余任务的计数口径

“剩余”指**本次勾选且尚未确认完成**的任务，不是界面总卡片数，也不是最初勾选数。每次回到稳定列表后重新计算：

- 已完成、未勾选项不计数。
- 五环暂时活跃度不足、竞技场暂时没有扫帚，仍是未完成项；不能为了判断三项阈值而先从计数中删除。
- 已确认正在执行的普通任务先继续等待，不因大理寺优先规则中断正在进行的任务。

### 选择下一项

1. 剩余 **≤3 项且包含大理寺答题**：优先大理寺，有扫帚用扫帚，无扫帚走自动答题；优先级高于其他任务的扫帚完成。
2. 未触发上述条件时，优先使用当前可确认的扫帚按钮，顺序为：**卓越竞技场 → 宝图任务 → 大理寺答题**。
3. 其余任务按当前列表顺序领取；五环是否暂缓见下一节，竞技场不进入普通领取流程。
4. 每项完成或任务奖励新增扫帚后，重新读取列表、判断完成状态和优先级，不沿用旧按钮位置或旧扫帚数量。

例：剩余五环、宝图、大理寺共 3 项时，先做大理寺；剩余 4 项且竞技场有扫帚时，仍先扫竞技场，完成后再按新的剩余数判断。

### 五环与活跃度

- 五环需要总活跃度达到 **50**。读取普通日常页下方绿色活跃度条及 50 刻度；单个任务的活跃度行、左上角「本日经验」百分比都不是总活跃度。
- 只在正常进入普通日常页、点击扫帚前顺便读取。轮到五环时不专门退出扫帚列表查看活跃度。
- 已确认达到 50 时，按上述优先级和列表顺序处理；五环在前面就可以先做，**不固定排到最后**。
- 不足或读数未知且还有其他可执行任务时，先做其他项，正常返回列表时再判断。
- 按用户确认的游戏规则，其他可执行任务做完后活跃度足够；最后仅五环可执行时，允许尝试领取。无扫帚的竞技场不能阻塞这一步。仍须确认五环已开始，不能据此假定领取成功。

### 卓越竞技场的例外

- 只有唯一、明确识别到「立即完成」或「一键完成」时，才允许使用扫帚；绝不点「前往」。
- 没有可确认的扫帚按钮，包括只看到「前往」、按钮文字漏识别或多个候选时，将未完成的竞技场保留为待处理，继续其他任务，不因它等待列表稳定超时。
- 日次数 3/3 即为完成，即使界面还有「前往」按钮也跳过。
- 只剩不可执行的竞技场时，返回 `needs_attention` 和待处理项，不伪报全部完成，也不额外等待任务间隔。

## 3. 已校准的领取路线

| 任务 | NPC | 普通领取选项 |
| --- | --- | --- |
| 帮派 | 帮派总管 | 帮派任务 |
| 五环 | 云游大师 | 我自己去拯救苍生！ |
| 师门 | 聂小倩 | 师门任务 |
| 宝图 | 店小二 | 宝图任务（文牒通关）优先；否则宝图任务 |
| 大理寺首次参加 | 大理寺官员 | 我要参加有奖问答 |
| 大理寺已有进度 | 大理寺官员 | 大理寺答题（未完成） |

- NPC 与选项必须同时确认，不因出现相似文字就点其他对话项。其他门派师门 NPC 尚需校准。
- 当前截图 OCR 会将「前往」读为「前注」、将「店小二」读为「店小」；只在已校准的卡片按钮或对应宝图对话中兼容，不扩展成全局模糊匹配。
- 宝图按完整选项文字区分普通领取和文牒通关。文牒后直接核对列表；没有确认完成则暂停，不重复消耗。
- 宝图结束的「宝图任务已完成，是否开始挖宝」倒计时弹窗优先点「取消」，不加普通输入前的额外停顿，不主动确认使用藏宝图。错过弹窗不单独作为终止后续任务的理由；未知页面仍保留保护。
- 扫帚操作未确认完成时暂停，不重复点击，也不自动改用另一条路线再次消耗。

## 4. 开始与完成的识别边界

### 确认任务已经开始

普通领取后，必须识别到右侧对应任务的有效进度，再进入等待；重启助手时也使用相同依据：

- 同一 OCR 行内包含完整任务文字与带括号的正数进度，例如「帮派教训武官（1/10）」；同一行拆开的文字可以合并。
- 当前数必须大于 0 且不大于总数。
- 「帮派悬赏」、跨行拼出的无关比例、0 次进度均不算已开始。
- 已在执行的所选任务继续等待，不重新领取；检测到未勾选的普通任务正在执行时，暂停并提醒等待或勾选该项。

曾出现“没有真正领取帮派却进入长时间等待”的故障；应修复进度识别，不能靠加长等待掩盖。

### 列表稳定与完成判定

列表必须连续两次识别结果一致才用于调度。奖励提示、遮挡或状态变化时重读，最多等待 15 秒。

| 画面情况 | 处理 |
| --- | --- |
| 日次数可靠达到上限 | 已完成；竞技场 3/3 仍有前往按钮也跳过 |
| 标题已识别，卡片排到列表底部且被扫帚面板遮挡 | 按用户确认的排序规律视为完成，次数可保留未知，不阻塞其他任务 |
| 非竞技场完整卡片没有领取／扫帚按钮，且没有明显青色按钮漏识别 | 视为完成，次数只作辅助 |
| 非竞技场仍有明显青色领取按钮，但文字读不清，或按钮不唯一 | 重读；持续无法确认则暂停，不视为完成 |
| 次数漏字、分母异常或读不清，但领取按钮已确认 | 次数保留未知，不单独因此暂停 |
| 所选任务标题始终缺失，包括大理寺 | 暂停，不据此宣称完成 |

仅任务追踪消失、屏幕中央小环节「任务完成」、答完最后一题、奖励动画或等待时间到了，都不足以确认整项日常完成；需要回到列表核对。

## 5. 三种等待时间

| 等待类型 | 当前规则 | 设置与适用范围 |
| --- | --- | --- |
| 普通日常完成到下一项 | 随机 10 秒～界面最大值，**默认最大值 180 秒** | 只填最大秒数，整数且至少 10；包括宝图文牒通关 |
| 扫帚快速完成或大理寺完成到下一项 | 随机 **8–15 秒**，留出奖励动画时间 | 替代普通任务间隔，不叠加 |
| 单次普通输入前 | 公共规则要求随机 **0.3–1 秒**，见 [AGENTS.md](../AGENTS.md#模拟器自动输入) | 与上面两种任务间隔不同；挖宝取消跳过额外停顿 |

- 只有确认还有下一项可执行时，才等待任务间隔；首次启动、最后一项完成或只剩不可执行项时不额外等待。
- 任务间隔可停止，结束后重新截图并稳定识别列表，再选下一项；不能点等待前选出的旧目标。
- 最大值在运行中不可修改，仅本次打开助手有效，不持久化，重启恢复 180。只改默认值不能连带修改任务轮询、超时、逐题或 200 环节奏。
- 早期会话中的 30–300 秒、10–300 秒和“扫帚／大理寺后立即继续”均已被上述规则替代；不再增加一套任务切换前短停顿。

### 普通任务执行中的等待

确认帮派、五环、师门或普通宝图开始后，交给游戏自动执行，不逐环领取、不操作战斗。

- 默认每约 5 秒截图检查完成提示，GUI 复用同一张截图，不额外取图。
- 连续两帧出现可靠完成对话，或宝图出现挖宝弹窗时，提前回列表核对。
- 没有可靠提示时，以帮派 7 分钟、五环 3 分钟、师门 9 分钟、宝图 5 分钟为兜底核对时间，不仅凭耗时判断完成。
- 列表仍未完成时约每 30 秒再核对；超过预估及额外 5 分钟仍未完成则暂停，不重复领取下一项。
- 「断开 / 停止」阻止后续输入并等待当前调用退出；已领取的游戏内自动任务不会因此停止。保留设备互斥锁，不绕过正在使用的连接。

## 6. 大理寺与共享答题策略

大理寺、200 环和独立答题沿用同一账号题库与策略；日常只负责导航、调用共享答题入口和最终列表确认，不另建随机答题器或专用题库。

- 支持 2–4 个选项，不要求任务标题或弹窗标题。选项文字未读清时，确认所有标签、数量和按钮后随机兜底；正常策略分支若存在唯一匹配的已验证题库答案且对应选项已读清，则优先该答案。不调用 AI、不学习；按钮、标签或同题无法确认仍暂停。
- 「正常答题概率」默认 100。设为 60 表示每题 60% 先查已验证题库；未命中且勾选 AI、配置有效时问 AI，否则随机；另 40% 直接随机。不是保证 60% 答对率。
- 「完全随机」忽略题库和 AI；同一题的预览、复核和提交沿用同一次选择，保留防重复提交与调用次数上限。
- AI 默认关闭。启用后请求失败或超限时暂停，不自动重试、不用随机答案掩盖错误。
- 自动学习只依据本次提交后、同题同选项上唯一可靠的正确对勾；错误揭示时收录对勾答案，不收录错选项。变色或切题本身不证明正确。完整要求见 [统一答题与题库学习](../AGENTS.md#统一答题与题库学习)。

## 8. 验收、排障与已知差距

### 离线回归要求

在项目根目录使用 Windows 虚拟环境，显式启用 UTF-8：

```bash
./.venv/Scripts/python.exe -X utf8 -m unittest discover -s tests -p test_daily_tasks.py -q
./.venv/Scripts/python.exe -X utf8 -m unittest discover -s tests -q
```

界面测试可设置 `QT_QPA_PLATFORM=offscreen` 离屏运行。回归至少覆盖：

- 1–3 项大理寺优先、4 项保持原优先级、已完成／未勾选不计数，活跃度不足的五环不被错误从计数中删除。
- 五环活跃度阈值、只在自然导航时检查、不固定最后；无扫帚竞技场不阻塞其他任务和最后可执行的五环。
- 竞技场按钮漏识别不整页暂停、3/3 跳过；其他任务的未知按钮保护保留。
- 帮派公告与跨行比例不误判为正在执行；底部遮挡完成、标题缺失拒绝及两帧列表稳定。
- 大理寺扫帚／首次参加／继续答题三条路径，共享策略参数和完成后列表核对。
- 10–180 秒默认普通间隔、8–15 秒奖励间隔、显式自定义最大值、等待期间取消及等待后重读。
- 普通输入随机范围、落点边界、停顿中停止、截图过期、停顿后页面或按钮变化时不误点。

日常诊断默认写入 [data/maa/daily/](../data/maa/daily/) 的 screen.png、ocr.json 和 performance.json。OCR 可能只覆盖按需区域，缺少某区域记录不等于整帧未识别；分享前检查账号、聊天等隐私。耗时和诊断指标不等于真实领取成功。

### 待对齐／待实机验证

- **点击复核差距**：当前 [DailyRunner.tap](../daily_tasks.py) 在随机停顿后只复查原截图的时效与失效状态，尚未重新截图、确认页面并重新定位按钮，不满足公共输入规则。相关修改与验收必须按公共规则补齐，不能将现有离线通过当成这项保护已实现。
- **旧测试与旧文案**：日常落点测试仍注入 0.15／0.35 秒，不能证明当前 0.3–1 秒随机范围；部分历史文档写“大理寺随机答题／不调用 AI”，实际后端已传递共享策略，以本文章节 6 及后端实现为准。
- **真实反馈素材**：正确对勾检测已有合成图验证，真实答对／答错反馈仍需原图校准；不得将其表述为实机学习已验收。
- **连续执行与奖励动画**：完整自动领取、五环活跃度判断、竞技场跳过后的续调度、大理寺续答与完成回列表，以及 8–15 秒奖励动画等待仍需实机验收。用户手动完成并提供截图，不等于助手自动点击已通过。

后续业务变更先更新本文对应规则和离线回归，再单独记录实机验收证据。
