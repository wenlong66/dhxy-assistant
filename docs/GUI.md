# Windows GUI 使用说明（v0.3.0）

这个界面是真正的 PySide6 Windows 桌面程序，入口是 `gui_app.py`，不是静态设计图。
它调用现有的 `maa_adapter.py`、`quiz_vision.py`、`quiz_core.py`，没有重写 OCR 或题库。
目前支持大理寺普通知识题的单题识别、查询、单次提交和本轮连续自动答题，
以及实验接入的帮派、五环、师门、宝图自动领取与完成检查，宝图文牒通关及宝图、竞技场的金扫帚操作。
以上流程仍需真实连续执行验收，不代表全部日常均已自动化。

## 快速开始

免安装版使用者：完整解压发布 ZIP 后双击 `DHXY-Assistant.exe`，无需安装 Python，连接步骤从下方第 3 步开始。
源码维护者可双击 `build_windows.bat` 重新构建；数据位置、升级与构建验收见 [Windows 免安装版说明](WINDOWS_BUILD.md)。

以下为源码运行步骤：

1. Windows x64 电脑先安装 [Python 3.11](https://www.python.org/downloads/) 与 Git；
   [配置 Git](https://git-scm.com/) 后获取项目 `git clone https://github.com/wenlong66/dhxy-assistant.git`。
2. 在仓库根目录双击 **`setup_gui.bat`**。脚本创建 `.venv`、安装 `requirements-gui.txt`，
   然后下载和校验中文 OCR 模型。需要能访问 Python 软件包源及 GitHub 模型文件。
   安装模型的具体版本和校验信息见 `setup_ocr.py`。
3. 启动 Android 模拟器，安装与你的账号渠道相符的《大话西游》手游并**手动登录**。
   建议固定横屏 1280×720，打开 ADB 本地调试；不同模拟器端口不同。
4. 双击 **`start_gui.bat`**，点击「扫描设备」→选择实例→「连接」。
   自动发现失败时，到「连接设置」填写 ADB 可执行文件路径和真实实例地址，保存后连接。
   连续答题可直接点击「开始自动答题」；后续第 5～8 步为单题手动调试流程。
5. 单题调试时，手动进入游戏里的**大理寺答题**题目界面，点击「OCR 识别当前题」。
   核对题目、OCR 和区域框图（`data/maa/inspection/overlay.png`），确认无漏字、串行和区域错位。
6. 点击「预览本题答案」：按正常答题概率查题库／可选 AI 或随机选择，不点击游戏；启用 AI 后预览也可能产生费用。
7. 单题手动提交先完成 OCR 检查并核对布局，再点击「提交本题一次」确认。
8. 提交后若在同一道题上识别到唯一正确对勾，自动收录对应答案；答错后揭示的正确选项也收录。
   未识别到可靠反馈时不收录，可在「本地题库」填写 `attempt_id` 与明确结果补录。

「校验答题界面」和「OCR 识别当前题」均检查题号、题干和全部选项，不读取顶部标题文字，避免公告遮挡造成误判。
支持 A/B、A/B/C 和 A/B/C/D；只将没有答案文字及可信字母的末尾区域视为不存在。全部选项标签和已校准按钮确认后，部分选项文字读不清可随机兜底；正常答题分支存在唯一匹配的已验证题库答案且对应选项已读清时优先该答案。不完整题目不调用 AI、不学习，按钮或标签无法确认仍暂停。不同任务使用相同策略和账号题库，仅画面布局分别校准。
「正常答题概率」为 0–100（默认 100）：60 表示 60% 概率先查已验证题库，未命中且勾选「启用 AI」时调用 AI，否则随机；另外 40% 直接随机，不保证 60% 答对率。「完全随机」忽略题库和 AI。模型 ID 和 API Key 在本地 `config/ai.local.json` 填写（字段 `model`、`api_key`，模板见 `config/ai.example.json`），界面无需输入；每次启动答题会重新读取。界面保留 AI 勾选和每日调用上限，AI 默认关闭。本地文件明文保存密钥，已加入 Git 忽略，不要分享。
大理寺从当前题处理到本轮最后一题；已校准的普通选择题弹窗可直接调用相同逻辑处理当前题，不要求活动或任务标题。
提交前随机等待0.3–1秒，等待可停止；之后重新截图核对同题和按钮，按钮内部随机取点，保留防重复提交。
提交后只在同题上识别到唯一正确对勾才学习；按钮不变色但出现正确对勾也可收录。未看清反馈不猜、不收录。
**对勾检测目前以合成图验证，真实反馈原文件尚不可访问；需要实图校准后再验收自动收录。**

也可以用 PowerShell 代替批处理：

```powershell
py -3.11 -m venv .venv
$PY = ".\.venv\Scripts\python.exe"
& $PY -m pip install -r requirements-gui.txt
& $PY setup_ocr.py
& $PY setup_ocr.py --verify
& $PY gui_app.py
```

若第 3 步出现 `Remote end closed connection without response`，表示下载模型时连接被远端或中间网络关闭，
与 pip 的更新提示无关。安装器会显示当前文件，对断连、超时和下载不完整最多尝试 3 次；
首次失败后自动改用 GitHub 官方 API 下载同一固定版本，后续文件也使用该接口。
仍失败时，检查网络或代理是否能访问 `raw.githubusercontent.com` 和 `api.github.com`，然后只重试模型安装：
`& .\.venv\Scripts\python.exe setup_ocr.py`，成功后运行 `start_gui.bat`。
不要关闭 TLS 校验；全部模型通过长度和哈希校验后才会替换原文件。

## 停止、暂停与费用

模拟器内的按钮只在已识别或校准的区域内取点，不固定点击中心。普通点击与 200 环列表滑动前会加 0.15–0.35 秒的随机短停顿；答题在最终截图复核前加入这段等待。挖宝弹窗的「取消」不额外等待，任务轮询和超时设置保持不变。

### 日常任务

1. 重启新版助手并连接设备，保持游戏主界面，或已经打开的活动面板。
2. 勾选要执行的日常任务，点击「开始日常任务」：自动打开左上角「活动」，再点击右下角扫帚进入日常任务列表。
   活动面板已打开时直接点击扫帚，不切换任何页签；已经进入扫帚列表时跳过这两步。日常包含勾选的大理寺答题，沿用统一题库／可选 AI／随机设置。
   大理寺有扫帚时直接完成；无扫帚时识别「大理寺官员」对话，首次选「我要参加有奖问答」，已有进度则选「大理寺答题（未完成）」，随后按右侧正常答题概率查库／可选 AI／随机。识别不到入口则暂停，提交最后一题后仍需回列表核对。
   入口点击后未打开会重新截图再试，每步最多 3 次；已打开时不重复点击。完成任务后返回列表也走同一流程。
   遇到「用了金扫帚，日常不用愁」引导时自动点击底部对话区关闭，再重新打开并核对任务列表；5 秒内仍未确认关闭则暂停，不连续点击。
3. 「检查日常列表」是可选的只读调试功能：需手动打开列表，只截图和 OCR，不点击游戏，不是自动执行的前置步骤。
4. 会自动消耗已有金扫帚；按当前「立即完成」按钮判断可用性，不依赖难以识别的红色数量。
   本次勾选且尚未完成的日常不超过 3 项时，若还有大理寺答题则优先完成它（有扫帚用扫帚，无扫帚自动答题）；已完成及未勾选项不计数。超过 3 项时优先竞技场、宝图、大理寺的扫帚完成，其余所选任务按当前列表顺序处理，五环不再固定最后；不自动处理野外封妖。
   正常进入普通日常页、点击扫帚前顺便检查绿色活跃度条是否达到 50，轮到五环时不专门返回。达到 50 按列表顺序领取；不足或刻度未识别先做其他任务，沿正常返回列表流程重新判断。仅剩五环时按用户确认的规则执行，不再因旧的活跃度判断不足而留下待处理；仍保留领取后确认开始和超时检查。
   「任务最大间隔」只填最大秒数（至少 10，默认 180）：普通日常完成且仍有下一项可执行时，随机等待 10 秒至该最大值，再重新截图核对并执行；金扫帚快速完成及大理寺答题完成后随机等待 8–15 秒，留出奖励动画时间，不叠加长间隔。首次启动、最后一项完成或只剩不可执行项时不额外等待；等待期间可停止。该值运行中不可修改，不保存，重启恢复默认；不影响答题逐题、200 环每环及点击前短停顿。
5. 普通任务只领取一次，确认任务进度后等待游戏自动执行；帮派、五环、师门、宝图默认每约 5 秒截图检查完成提示，预览直接复用这张截图，不额外取图。
   连续两帧出现明确的完成对话，或宝图出现「任务已完成，是否开始挖宝」弹窗时，提前核对列表；仅任务追踪消失不算完成。停止功能保持可用。
   没有可靠完成提示时，仍按帮派 7 分钟、五环 3 分钟、师门 9 分钟、宝图 5 分钟兜底核对，不仅凭时间判定完成。
   任务标题已识别、卡片排到列表底部且被扫帚面板遮挡时，按已完成处理，继续执行其他任务，不因卡片未完整显示而暂停；看不清的次数保留为未知。
   除竞技场外，完整卡片没有「前往／立即完成／一键完成」按钮时按已完成处理；次数只作辅助。
   次数漏字或读不清不再直接暂停，也不会把活跃度行当作次数。其他任务仍有青色领取按钮但文字没识别到时，继续等待识别。
   未完成时每约 30 秒再检查，超过估时及额外 5 分钟则暂停。耗时只有一轮样本，不能单独判定完成。
6. 宝图在店小二处按完整文字识别按钮，有「宝图任务（文牒通关）」时优先点击并立即核对完成；否则选择普通「宝图任务」，确认右侧进度后按同样的 5 秒周期检查，不再固定等满 5 分钟。
   宝图结束后的挖宝弹窗优先取消；错过弹窗也会继续识别下一项，不主动确认使用藏宝图。文牒操作未确认完成时暂停，不重复消耗。
7. 「断开 / 停止」停止后续点击并释放连接；已领取的游戏内自动任务仍会继续。
   重新启动时，仅将右侧同一行内完整的任务进度（如「帮派教训武官（1/10）」）作为继续等待的依据；帮派悬赏、跨行拼出的无关次数或 0 次进度不算任务已开始，不跳过普通领取。

卓越竞技场只使用明确识别到的金扫帚按钮，不点「前往」。没有可确认的扫帚按钮时，未完成的竞技场保留为待处理，继续执行其他任务；它不影响最后一项可执行的五环。
奖励提示挡住列表或状态正在变化时，会先等待重读，最多 15 秒，并要求两次状态稳定后才操作。
持续列表缺项、未知页面或按钮无法确认时保存到 `data/maa/daily/screen.png` 和 `ocr.json`，暂停后可将截图用于排查。
入口图标沿用当前 16:9 截图校准位置；列表滚动、门派 NPC 不同或 UI 改版需要补充校准，程序不会盲点其他选项。

### 答题控制

- 「预览本题答案」「提交本题一次」「开始自动答题」「暂停画面预览」集中在答题控制内，分两行排列。
- 下方仅显示一行结果摘要；点击「查看详情」可打开可复制的完整回执。详情窗口不阻塞主界面，收到新结果时同步更新；日常列表及 200 环结果也在此查看。
- 勾选「完全随机答题（忽略题库）」后，从当前实际识别出的二至四项答案中随机选一个。
  所有模式均读取真实题干及答案文字；同一画面的预览与提交沿用相同选择，不在复核时重新抽签。
  随机答对可学习，答错但揭示正确选项也学习；未确认正确标记时仅保留提交记录，不写答案题库。
- 所有答案点击均在所选按钮内部随机取点，避开约 10% 的边缘，不再固定点击中心。按题作答仍读取完整题干和答案。
- 「暂停画面预览」只停止周期性截图，**不会暂停自动答题，也不会中断正在进行的 AI 请求或原生操作**。
- 「断开 / 停止」将设置取消标志；还没执行的点击会检查该标志。
  已经发往设备的点击无法撤回，已发出的 OpenAI API 请求也可能产生费用。
  操作线程要等当前请求返回后才会释放连接，不会强制终止正在运行的原生调用。
- 「预览本题答案」和「提交本题一次」只处理一道题；「开始自动答题」才会连续处理。
- GUI 的 AI 默认关闭；勾选并填写参数后，仅正常答题分支的题库未命中会调用 AI。请求失败、超限时暂停，不自动重试或随机掩盖错误。独立命令行核心的显式 OpenAI 功能保持不变。
- OpenAI Key 从本地 `config/ai.local.json` 读取，该文件明文保存且不提交 Git；不会写入设备配置 `config/local.json`、SQLite、截图或日志；
  也不会上传整个游戏画面。密钥不应提交 Git。
- OCR 模型和游戏截图仅放在本地 `.gitignore` 所排除的目录内。

## 限制和安全

**没有在你的 Windows 电脑、模拟器账号、Maa 原生库和 OpenAI 账号上做过真实端到端验证。**
本次测试为离线业务逻辑测试与 Python 编译；Qt 控件的现场运行还需在安装 PySide6 的电脑验收。
首先验证 `扫描→连接→截图→OCR`，不建议直接开启自动点击。

若检测到异常验证、登录页、不认识的弹窗、OCR 低置信度或画面比例变化，工具应暂停。
不包含游戏内存修改、注入或绕过反作弊技术；使用自动化操作仍可能违反游戏条款并带来账号处罚风险。

## 源码结构

- `gui_app.py`：真实 PySide6 窗口、设备后台串行队列及信号、按钮、日志。
- `gui_backend.py`：与 GUI 解耦的设备控制、截图、OCR 调用、答题、题库查询与反馈。
- `maa_adapter.py`：固定 Maa 5.15.0 的 Android ADB 适配器。
- `quiz_vision.py`：严格页面校验、ROI 与单题安全提交；添加取消检查。
- `quiz_core.py`：SQLite／OpenAI，API Key 可仅通过内存参数注入。
- `requirements-gui.txt`：PySide6＋原设备依赖。
- `setup_gui.bat`、`start_gui.bat`：Windows 初次安装与启动。

最新完整模拟器说明见 [EMULATOR.md](EMULATOR.md)，离线测试范围见 [VALIDATION.md](VALIDATION.md)。
