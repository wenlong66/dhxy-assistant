# Windows GUI 使用说明（v0.3.0）

这个界面是真正的 PySide6 Windows 桌面程序，入口是 `gui_app.py`，不是静态设计图。
它调用现有的 `maa_adapter.py`、`quiz_vision.py`、`quiz_core.py`，没有重写 OCR 或题库。
目前支持大理寺普通知识题的单题识别、查询、单次提交和本轮连续自动答题，
以及实验接入的帮派、五环、师门自动领取与完成检查，宝图和竞技场的金扫帚操作。
宝图普通领取尚未接入，不代表全部日常均已自动化。

## 快速开始

1. Windows x64 电脑先安装 [Python 3.11](https://www.python.org/downloads/) 与 Git；
   [配置 Git](https://git-scm.com/) 后获取项目 `git clone https://github.com/wenlong66/dhxy-assistant.git`。
2. 在仓库根目录双击 **`setup_gui.bat`**。脚本创建 `.venv`、安装 `requirements-gui.txt`，
   然后下载和校验中文 OCR 模型。需要能访问 Python 软件包源及 GitHub 模型文件。
   安装模型的具体版本和校验信息见 `setup_ocr.py`。
3. 启动 Android 模拟器，安装与你的账号渠道相符的《大话西游》手游并**手动登录**。
   建议固定横屏 1280×720，打开 ADB 本地调试；不同模拟器端口不同。
4. 双击 **`start_gui.bat`**，点击「扫描设备」→选择实例→「连接」。
   自动发现失败时，到「连接设置」填写 ADB 可执行文件路径和真实实例地址，保存后连接。
   连续答题可直接点击「开始自动答题」；后续第 5～8 步为单题手动调试流程。
5. 单题调试时，手动进入游戏里的**大理寺答题**题目界面，点击「OCR 识别当前题」。
   核对题目、OCR 和区域框图（`data/maa/inspection/overlay.png`），确认无漏字、串行和区域错位。
6. 点击「预览本题答案」：默认只查本地题库，不花费 OpenAI 额度，也不会点击游戏。
   如果需要 AI，可勾选允许查询、填写你有权限的模型 ID 与 API Key。
7. 首次提交前必须已完成有效的 OCR 检查，勾选已核对布局。
   允许未验证 AI 候选则另外勾选「允许试答」。点击「提交本题一次」并再次确认。
8. 看到实际结果以后，在「本地题库」填写 `attempt_id`、实际答对/答错/不明确及依据。
   仅确认正确的记录进入已验证题库；点击成功不等于答对。

「校验答题界面」和「OCR 识别当前题」均检查题号、题干和全部选项，不读取顶部标题文字，避免公告遮挡造成误判。
支持 A/B 两选项、A/B/C 三选项和 A/B/C/D 四选项题；只将没有答案文字及可信字母的末尾区域视为不存在，部分识别失败仍会暂停。
非随机的单题手动提交需要完整 OCR 检查通过，并勾选布局确认；随机模式只检查题号和选项按钮，不需要预先识别答案文字。

连续自动答题：连接设备，手动进入大理寺题目后，直接点击「开始自动答题」，确认启动一次即可。程序自行识别、校验和提交，从当前题连续答到本轮最后一题；不需要先手动 OCR 或勾选布局确认。
勾选「随机答题」时连续随机提交；未勾选时题库优先，未命中用 AI 审题并自动提交候选，需要先填写模型 ID 和 API Key。
自动模式不受单题的「题库未命中时询问 OpenAI」和「允许试答 AI 候选」开关限制，启动弹窗会说明模式及费用。
提交后等待题号递增，同一题不会重复点；短暂 OCR 失败、画面变化会自动重新读取，已获取的 AI 答案使用缓存，不重复请求。
等待超时、题号跳变、没有可提交答案或 AI 失败时暂停。
「断开 / 停止」可随时中止后续提交。循环不自动判断答对/答错，也不会把提交成功当作已验证答案。

也可以用 PowerShell 代替批处理：

```powershell
py -3.11 -m venv .venv
$PY = ".\.venv\Scripts\python.exe"
& $PY -m pip install -r requirements-gui.txt
& $PY setup_ocr.py
& $PY setup_ocr.py --verify
& $PY gui_app.py
```

若第 3 步出现 `Remote end closed connection without response`，表示下载模型时连接被远端或中间网络关闭，
与 pip 的更新提示无关。安装器会显示当前文件，对断连、超时和下载不完整最多尝试 3 次；
首次失败后自动改用 GitHub 官方 API 下载同一固定版本，后续文件也使用该接口。
仍失败时，检查网络或代理是否能访问 `raw.githubusercontent.com` 和 `api.github.com`，然后只重试模型安装：
`& .\.venv\Scripts\python.exe setup_ocr.py`，成功后运行 `start_gui.bat`。
不要关闭 TLS 校验；全部模型通过长度和哈希校验后才会替换原文件。

| 模拟器扫描/连接 | 是（待实机验证） | Maa 的 ADB Toolkit，可手动配置地址；单设备连接 |
| 实时画面 | 是（待实机验证） | 连接成功后约两秒只读截图一次，不自动点击 |
| 保存截图/ROI | 是 | 本地输出 PNG 和区域框图，供调布局 |
| OCR 调试 | 是（待实机验证） | Maa 本地中文 OCR，严格校验题号、题干、二至四项答案 |
| AI 答案预览 | 是（API 仍需你的账号实测） | 题库优先、AI 可选；密钥留在内存 |
| 单题执行 | 是（待实机验证） | 必须显式授权，最多点击一次；调用后重新确认场景 |
| 自动答题 | 是（连续实机流程待验证） | 随机或题库优先、AI 兜底；从当前题到最后一题，每题最多点击一次 |
| 本地题库 | 是 | 搜索和查看最近 200 条，录入实际反馈 |
| 师门/帮派/五环 | 实验接入 | 按当前列表顺序领取，约 9/7/3 分钟后首次检查，核对完成次数再切换 |

| 自动登录／自动反馈／每日调度 | **否** | 仍需要开发和真实画面样本 |

## 停止、暂停与费用

### 日常任务

1. 重启新版助手并连接设备，保持游戏主界面，或已经打开的活动面板。
2. 勾选要执行的日常任务，点击「开始日常任务」：自动打开左上角「活动」，再点击右下角扫帚进入日常任务列表。
   活动面板已打开时直接点击扫帚，不切换任何页签；已经进入扫帚列表时跳过这两步。日常不会调用 AI，也不会自动进入大理寺答题。
   入口点击后未打开会重新截图再试，每步最多 3 次；已打开时不重复点击。完成任务后返回列表也走同一流程。
3. 「检查日常列表」是可选的只读调试功能：需手动打开列表，只截图和 OCR，不点击游戏，不是自动执行的前置步骤。
4. 会自动消耗已有金扫帚；按当前「立即完成」按钮判断可用性，不依赖难以识别的红色数量。
   优先竞技场、宝图，随后按列表从左到右、从上到下处理所选任务。每项完成后重新读取排序和扫帚可用性。
5. 普通任务只领取一次，然后等待游戏自动执行；帮派约 7 分钟、五环约 3 分钟、师门约 9 分钟后首次核对。
   已识别到完整任务卡片，且没有「前往／立即完成／一键完成」按钮时按已完成处理；次数只作辅助，竞技场显示 3/3 时即使还有「前往」也跳过。
   次数漏字或读不清不再直接暂停，也不会把活跃度行当作次数。若画面仍有青色领取按钮但文字没识别到，则继续等待识别。
   未完成时每约 30 秒再检查，超过估时及额外 5 分钟则暂停。耗时只有一轮样本，不能单独判定完成。
6. 宝图扫完后优先取消挖宝弹窗；错过弹窗也会继续识别下一项，不主动确认使用藏宝图。
7. 「断开 / 停止」停止后续点击并释放连接；已领取的游戏内自动任务仍会继续。
   重新启动时若右侧可识别到所选任务正在执行，则等待检查，不重复领取。

尚未完成的竞技场没有可用扫帚时只记录为待处理，不执行普通竞技场；
轮到无扫帚的宝图时暂停并提示补充普通领取流程。
奖励提示挡住列表或状态正在变化时，会先等待重读，最多 15 秒，并要求两次状态稳定后才操作。
持续列表缺项、未知页面或按钮无法确认时保存到 `data/maa/daily/screen.png` 和 `ocr.json`，暂停后可将截图用于排查。
入口图标沿用当前 16:9 截图校准位置；列表滚动、门派 NPC 不同或 UI 改版需要补充校准，程序不会盲点其他选项。

### 答题控制

- 勾选「随机答题（不查题库、不调用 AI）」后，从当前实际识别出的二至四项答案中随机选一个。
  随机模式只识别题号和 A/B/C/D 按钮字母，不识别题干含义或答案文字；题号用于换题及重复提交保护。
  「预览本题答案」只显示选项字母；「提交本题一次」确认后才点击，无需先点完整 OCR 或勾选布局确认。
  同一题画面的预览与提交沿用同一个随机选择，无需勾选「允许试答尚未验证的 AI 候选」。
  随机选择不调用 AI、不改写答案题库，仅保留提交及反馈记录。
- 所有答案点击均在所选按钮内部随机取点，避开约 10% 的边缘，不再固定点击中心。按题作答仍读取完整题干和答案。
- 「暂停画面预览」只停止周期性截图，**不会暂停自动答题，也不会中断正在进行的 AI 请求或原生操作**。
- 「断开 / 停止」将设置取消标志；还没执行的点击会检查该标志。
  已经发往设备的点击无法撤回，已发出的 OpenAI API 请求也可能产生费用。
  操作线程要等当前请求返回后才会释放连接，不会强制终止正在运行的原生调用。
- 「预览本题答案」和「提交本题一次」只处理一道题；「开始自动答题」才会连续处理。
- 单题 API 请求默认关闭；自动答题未勾选随机时，启动确认后按需调用 OpenAI。每天默认最多 30 次请求（可调整）；
  这只是次数限制，不保证账单金额上限。回答成功也不代表游戏内正确。
- OpenAI Key 仅存在当前进程内存中，不会写入 `config/local.json`、SQLite、截图或日志；
  也不会上传整个游戏画面。密钥不应提交 Git。
- OCR 模型和游戏截图仅放在本地 `.gitignore` 所排除的目录内。

## 限制和安全

**没有在你的 Windows 电脑、模拟器账号、Maa 原生库和 OpenAI 账号上做过真实端到端验证。**
本次测试为离线业务逻辑测试与 Python 编译；Qt 控件的现场运行还需在安装 PySide6 的电脑验收。
首先验证 `扫描→连接→截图→OCR`，不建议直接开启自动点击。

若检测到异常验证、登录页、不认识的弹窗、OCR 低置信度或画面比例变化，工具应暂停。
不包含游戏内存修改、注入或绕过反作弊技术；使用自动化操作仍可能违反游戏条款并带来账号处罚风险。

## 源码结构

- `gui_app.py`：真实 PySide6 窗口、设备后台串行队列及信号、按钮、日志。
- `gui_backend.py`：与 GUI 解耦的设备控制、截图、OCR 调用、答题、题库查询与反馈。
- `maa_adapter.py`：固定 Maa 5.15.0 的 Android ADB 适配器。
- `quiz_vision.py`：严格页面校验、ROI 与单题安全提交；添加取消检查。
- `quiz_core.py`：SQLite／OpenAI，API Key 可仅通过内存参数注入。
- `requirements-gui.txt`：PySide6＋原设备依赖。
- `setup_gui.bat`、`start_gui.bat`：Windows 初次安装与启动。

最新完整模拟器说明见 [EMULATOR.md](EMULATOR.md)，离线测试范围见 [VALIDATION.md](VALIDATION.md)。
